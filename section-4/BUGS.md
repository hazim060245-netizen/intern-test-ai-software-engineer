## จุดที่สงสัย (Points of Inquiry)

1. **การกรอง `t.assigned_to === user.id` ใน `EmployeeTasks.jsx` (บรรทัดที่ 27):**
   - *ข้อสังเกต:* เมื่อพิจารณา Endpoint `GET /api/tasks` ใน `routes/tasks.js` จะพบว่า Server มีการกรองเงื่อนไข `WHERE assigned_to = req.user.id` มาให้อยู่แล้วสำหรับ Role ที่ไม่ใช่ Admin การกรองซ้ำใน React ฝั่ง Frontend จึงดูเหมือนซ้ำซ้อน
   - *เหตุผลที่ไม่ถือว่าเป็นบั๊ก:* พฤติกรรมนี้ถือเป็นแนวทาง **Defense in Depth (การป้องกันหลายชั้น)** ที่ดีทางฝั่ง Frontend เผื่อกรณีที่ API ส่งข้อมูลเกินมา จะช่วยรับประกันได้ 100% ว่า Employee จะไม่เห็น Task ของเพื่อนร่วมงานบนหน้าจอของตนเองอย่างแน่นอน

2. **การตรวจเช็ค `if (!isAdmin && status !== 'Done')` ใน `routes/tasks.js`:**
   - ในโค้ดเดิมมีเพียงเช็ค `if (!ALLOWED_STATUSES.includes(status))` และ `if (!isAdmin && task.status === 'Done' && status === 'To Do')`
   - แต่ตามกฎของระบบระบุชัดเจนว่า **"Employee เปลี่ยนได้เฉพาะ To Do → Done"** ดังนั้นหากมีสถานะใหม่เพิ่มเข้ามาในอนาคต (เช่น `In Progress`, `Archived`) Employee จะต้องไม่สามารถเปลี่ยนไปสถานะนั้นได้ จึงได้เพิ่มการตรวจเช็คที่รัดกุมนี้เพิ่มเติมในโค้ดที่แก้ไข
